# 第 0 章：开工前，先看这一页

## 0.1 这个项目要做什么

**一句话**：让板子能通过 4G 从云端下载新固件，自己完成升级。

**拆开看**：

```
① 板子连上 4G 网络           → A 负责
② 板子连上阿里云             → C 负责
③ 云端说"有新版本"           → C 负责
④ 板子把固件下载下来         → A 负责
⑤ 固件存到外部 Flash         → A + D 负责
⑥ 重启后把固件搬到运行区     → B 负责
⑦ 新固件跑起来               → B 负责
```

## 0.2 四个人的角色

| 成员 | 一句话职责 | 关键文件 |
|---|---|---|
| **A** | 让板子能联网、能下载 | `cat1.c` |
| **B** | 让下载的固件能跑起来 | `boot.c` `stmflash.c` |
| **C** | 让云端能认设备、能推升级 | `mqtt.c` |
| **D** | 把底层铺好，最后把大家合起来 | `spi.c` `main.c` |

## 0.3 时间安排（4 周）

| 周 | 目标 | 里程碑 |
|---|---|---|
| **W1** | 环境跑通，各自模块能单独验证 | 门禁 1：AT 指令可用 |
| **W2** | 各自功能写完 | 每个人能演示自己的模块 |
| **W3** | 集成联调 | 门禁 3：完整走通一次 OTA |
| **W4** | 异常加固 + 文档 + 答辩 | 门禁 4：4 类异常不变砖 |

## 0.4 最重要的一条规则

> **只改自己负责的文件。**
>
> 改别人的文件 → 冲突 → 返工 → 浪费时间。
>
> 唯一例外：`common.h` 要改，必须群里说一声，改完同步到两个工程。

## 2.3 理解框架的设计

```c
/*=====================================================================
 * 函数：CAT1_SendAT
 * 负责：A
 *
 * ★这是最核心的函数，其他都依赖它★
 *
 * 实现要点：
 *   1. 清标志：usart3_value.flag = 0; usart3_value.count = 0;

 *        }
 *   4. 超时返回 1

u8 CAT1_SendAT(char *cmd, char *expect, u16 timeout_ms)
{
    /* TODO【A】：实现 */
    return 1;
}
```

**你要做的**：
1. 读上面的注释（这是作业大纲）
2. 把 `/* TODO【A】：实现 */` 替换成真正的代码
3. 保留 `return` 语句（如果有）

**为什么要这样设计**：
- 函数签名已经定好 → 不会和其他人的接口冲突
- 注释写了实现要点 → 不用猜
- 留空 → 你真正动手写，答辩时能讲清楚

# 第 3 章：验证硬件（A 必做）

> **这一章是 A 的专属，但 B/C/D 也可以看看，理解整个系统的前提。**

## 3.1 第一步：量电压（10 分钟，最重要）

**为什么要做**：L511-2 模块的串口可能是 **1.8V 电平**，而 STM32 是 3.3V。直接接可能烧模块。

**怎么做**：

1. **只给 4G 模块供电**，不接单片机
2. 让模块开机（PWRKEY 拉低 1 秒以上）
3. 万用表打**直流电压档（20V）**
4. 黑表笔接模块 **GND**
5. 红表笔点模块的 **TXD 引脚**

**判断**：

| 测到 | 结论 | 怎么办 |
|---|---|---|
| **≈1.8V** | 模块是 1.8V 电平 | ⚠️ 必须买 **TXB0108** 电平转换模块 |
| **≈3.3V** | 模块是 3.3V 电平 | ✅ 可以直连 |
| **0V** | 模块没开机 | 检查电源，手动开机 |
| 数值乱跳 | 接触不良 | 重新测 |

**原理**：串口 TXD 空闲时保持高电平，空载量它的电压就是它的电平域。

> **把测到的数值记下来**，写进实验报告，答辩可能问。

## 3.2 第二步：USB-TTL 单独测模块

**为什么**：在接单片机之前，先用电脑确认模块是好的。这样出问题能分清是模块坏还是代码错。

**接线**（你手里的 DX-PJ15-V1.1）：

```
DX-PJ15          4G 模块
3V3     ───────  VBAT / VCC      ← 电源
GND     ───────  GND             ← 共地
TX      ───────  RXD             ← 交叉
RX      ───────  TXD             ← 交叉
```

> ⚠️ **不要接 VIN**（那是电源输入，不是输出）
> ⚠️ 4G 模块如果标 3.8V，优先试 `3V3` 脚（在 3.3~4.5V 范围内）

**电脑端设置**：

1. 插 USB
2. 设备管理器看是 **COM 几**
3. 打开串口助手（SSCOM / XCOM）
4. 参数：**115200, 8, N, 1**
5. **勾选"发送新行"**（很关键！）

**发第一条指令**：

```
AT
```

**期望回复**：

```
OK
```

> **收到 OK 就说明模块是好的，接线对了。**

## 3.3 第三步：逐条测 AT 指令

按顺序发，每条确认正常再下一条。

### 第 1 组：基础（肯定通用）

```
AT                → OK
ATI               → 型号/版本信息
AT+CPIN?          → +CPIN: READY
AT+CSQ            → +CSQ: 25,99      （第一个数 >10 可用）
AT+CREG?          → +CREG: 0,1       （0,1 或 0,5 = 已注册）
AT+CGATT?         → +CGATT: 1
```

**异常对照**：

| 返回 | 原因 | 解决 |
|---|---|---|
| 无回复 | TX/RX 接反 / 波特率错 / 没开机 | 逐项检查 |
| `+CME ERROR: 10` | SIM 卡没插好 | 重插 |
| `+CSQ: 99,99` | 没信号 | 接天线，靠近窗户 |
| `+CREG: 0,2` | 正在找网 | 等 10-30 秒 |
| `+CGATT: 0` | 没附着网络 | 等一会儿，或 `AT+CGATT=1` |

### 第 2 组：GPRS 承载（★关键★）

```
AT+SAPBR=3,1,"CONTYPE","GPRS"     → OK
AT+SAPBR=3,1,"APN",""             → OK
AT+SAPBR=1,1                      → OK
AT+SAPBR=2,1                      → +SAPBR: 1,1,"10.x.x.x"
```

**最后一条返回 IP 地址就成功了。**

**APN 填什么**（留空不行的话）：

| 运营商 | APN |
|---|---|
| 移动 | `CMNET` 或 `CMIOT` |
| 联通 | `3GNET` |
| 电信 | `CTNET` |

### 第 3 组：HTTP（★最关键★）

**前提**：准备一个能下载的小文件（几 KB），放在某个 HTTP 服务器上。

```
AT+HTTPINIT                              → OK
AT+HTTPPARA="CID",1                      → OK
AT+HTTPPARA="URL","http://xxx/test.bin"  → OK
AT+HTTPACTION=0                          → OK
   （等几秒）
   +HTTPACTION: 0,200,1024               （0=GET, 200=成功, 1024=长度）
AT+HTTPREAD=0,256                        → +HTTPREAD: 256
                                            <256 字节数据>
AT+HTTPTERM                              → OK
```

## 3.4 ⚠️ 门禁 1（第一周必须通过）

> **如果 `AT+SAPBR=1,1` 或 `AT+HTTPINIT` 返回 `ERROR`，立刻通知全组！**
>
> 说明移柯改了 AT 指令集，HTTP 方案不可行，要改走 MQTT 分片路线（工作量大增）。
>
> **这是全项目最大的风险点，必须第一周内确认。**

## 3.5 把结果存档

**把每一组的正常回复都截图**，整理成一个文档。

后面写代码出问题时，对比截图能快速判断：
- 是模块问题？（截图里明明是好的）
- 还是代码问题？（指令发错了）

# 第 4 章：写你的第一个函数

> 以 A 的 `CAT1_SendAT` 为例，其他人参考这个思路。

## 4.1 先理解这个函数要做什么

**目标**：发一条 AT 指令，等模块回复，判断是否成功。

**输入**：
- `cmd`：指令内容，如 `"AT"`
- `expect`：期望看到的关键字，如 `"OK"`
- `timeout_ms`：最多等多少毫秒

**输出**：
- `0`：收到了期望的回复（成功）
- `1`：超时（失败）

## 4.2 你的串口框架是怎么工作的

先看懂已有的代码（`usart.c`）：

```c
typedef struct {
    u8  data[1024];   // 接收缓冲
    u16 count;        // 已收字节数
    u8  flag;         // 1 = 收到一帧完整数据
} USART_Data;

extern USART_Data usart3_value;
```

**工作流程**：

```
模块发数据 → 串口中断 → 每收一个字节存到 data[]，count++
                       ↓
                    总线空闲 → 触发 IDLE 中断 → flag = 1
                       ↓
                    你的代码看到 flag == 1 → 处理数据
```

## 4.3 写代码

```c
u8 CAT1_SendAT(char *cmd, char *expect, u16 timeout_ms)
{
    u16 i;

    /* 1. 清标志，准备接收新数据 */
    usart3_value.flag  = 0;
    usart3_value.count = 0;

    /* 2. 发送指令（★必须加 \r\n，不加模块不响应★） */
    Usart3_SendString(cmd);
    Usart3_SendString("\r\n");

    /* 3. 循环等待 */
    for(i = 0; i < timeout_ms; i++){
        delay_ms(1);

        /* 收到一帧数据了 */
        if(usart3_value.flag){
            /* 检查是否含期望关键字 */
            if(strstr((char*)usart3_value.data, expect)){
                return 0;   /* 成功 */
            }

            /* 不是期望的，清掉继续等 */
            usart3_value.flag  = 0;
            usart3_value.count = 0;
        }
    }

    return 1;   /* 超时 */
}
```

## 4.4 三个容易踩的坑

**坑 1：忘记 `\r\n`**

AT 指令必须以回车换行结尾，不然模块不响应。

```c
Usart3_SendString(cmd);
Usart3_SendString("\r\n");    /* ← 不能少 */
```

**坑 2：`strstr` 参数类型**

`usart3_value.data` 是 `u8` 数组，`strstr` 要 `char*`，必须强转：

```c
strstr((char*)usart3_value.data, expect)   /* ✅ */
strstr(usart3_value.data, expect)          /* ❌ 编译警告 */
```

**坑 3：忘记清缓冲**

上一条指令的残留数据会干扰判断。每次发之前必须清：

```c
usart3_value.flag  = 0;
usart3_value.count = 0;
```

## 4.5 测试

在 `main()` 里写：

```c
int main(void)
{
    Usart1_Init(115200);    /* 调试串口 */
    Usart3_Init(115200);    /* 4G 模块 */
    CAT1_GPIO_Init();

    Usart1_SendString("\r\n===== AT 测试 =====\r\n");

    if(CAT1_SendAT("AT", "OK", 1000) == 0){
        Usart1_SendString("AT -> OK\r\n");
    }else{
        Usart1_SendString("AT -> 超时\r\n");
    }

    while(1);
}
```

**烧录，打开串口助手（USART1，115200）**

**期望看到**：

```
===== AT 测试 =====
AT -> OK
```

**看到这个，你的第一个函数就成功了。**

| **30 分钟** | 问同组的人（群里发问题 + 截图） |
| **1 小时** | 找 D（他是集成负责人，见得多） |
| **半天** | 全组一起看，或者跳过先做别的 |

> **不要一个人死磕一整天。** 项目有 4 周，卡一天就少一天。

## 6.2 提问的正确方式

**❌ 坏的提问**：

> "我的代码不工作，怎么办？"

**✅ 好的提问**：

> **现象**：`CAT1_SendAT("AT", "OK", 1000)` 一直返回 1（超时）
>
> **我已经排查**：
> 1. 用 USB-TTL 单独测过模块，发 AT 能收到 OK ✅
> 2. 波特率确认是 115200 ✅
> 3. 串口中断里加了 printf，能看到收到数据 ✅
>
> **猜测**：可能是 `strstr` 比较失败？
>
> **附件**：串口打印截图

**好提问的三个要素**：
1. **现象**（具体到什么函数、什么返回值）
2. **已排查**（证明你不是没试）
3. **猜测**（说明你有思考）

## 6.3 常见卡点预判

| 卡点 | 谁容易遇到 | 提前知道 |
|---|---|---|
| 串口收不到数据 | A、C、D | 检查波特率、TX/RX 是否交叉、共地 |
| 中断进不去 | 全员 | 检查 NVIC 配置、中断函数名拼写 |
| 程序跑飞 | 全员 | 检查 `VECT_TAB_OFFSET` |
| 模块反复重启 | A | 电源不足（要 1.2A） |
| 数据对不上 | A、D | 缓冲太小 / `memcpy` vs `strcpy` |
| 结构体乱码 | B、C | `common.h` 两边不一致 |

# 第 8 章：常见问题速查

## 8.1 环境问题

**Q：Keil 编译报 `cannot open source input file "stm32f10x.h"`**

A：缺 DFP 包。Keil → Pack Installer → 搜 `STM32F1` → 安装 `Keil.STM32F1xx_DFP`。

**Q：编译报 `undefined symbol`**

A：某个 `.c` 文件没加到工程里。右键 Group → Add Existing Files。

**Q：编译通过但烧录后没反应**

A：检查烧录地址。BootLoader 烧 `0x08000000`，APP 烧 `0x08008000`。

## 8.2 Git 问题

**Q：`git push` 提示 `Authentication failed`**

A：密码要用 Personal Access Token，不是账号密码。

**Q：`git push` 提示 `rejected - non-fast-forward`**

A：别人先推了。执行：

```bash
git pull --rebase
git push
```

**Q：改了代码但 `git status` 看不到**

A：可能改的是被 `.gitignore` 忽略的文件（如 `Objects/`）。

**Q：不小心改错了，想撤销**

```bash
git checkout -- 文件名     # 撤销未提交的修改
```

## 8.3 硬件问题

**Q：4G 模块反复重启**

A：电源不足。模块发射瞬间要 1.2A，必须独立供电 + 100μF 电容。

**Q：串口收到乱码**

A：① 波特率不对 ② 电平不匹配（1.8V 直连 3.3V）③ 没共地。

**Q：W25Q128 读 ID 不是 `0xEF4018`**

A：① CS 没拉低 ② SPI 没使能 ③ MISO 没接。

**Q：烧了 APP 但程序不跑**

A：`VECT_TAB_OFFSET` 没改成 `0x8000`。

## 8.4 代码问题

**Q：中断进不去**

A：检查 ① `NVIC_Init` 有没有调 ② 中断函数名是否和启动文件一致（`USART3_IRQHandler` 全大写）③ 有没有 `USART_ITConfig` 使能。

**Q：程序跑飞（HardFault）**

A：① 向量表没重定位 ② 栈溢出 ③ 访问空指针。

**Q：数据下载后对不上**

A：① 接收缓冲太小（要 1024）② 用了 `strcpy` 而不是 `memcpy` ③ 分片偏移算错。
