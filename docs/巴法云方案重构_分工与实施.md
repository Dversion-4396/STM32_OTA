# 巴法云方案重构 —— 分工与实施文档

> 编写日期：2026-10-27
> 背景：阿里云 IoT 无法使用，改用巴法云（bemfa）作为设备接入平台
> 影响范围：C 的全部工作重写，A 的 HTTP 下载部分不变，B/D 基本不受影响

---

## 第一部分：先搞清楚变了什么

### 1.1 阿里云 vs 巴法云 核心差异

| 项目 | 阿里云 IoT | 巴法云 | 影响 |
|---|---|---|---|
| **接入凭证** | 三元组（ProductKey 11位 + DeviceName + DeviceSecret 32位） | **只有一个 UID（私钥，32位）** | 大幅简化 |
| **密码算法** | HMAC-SHA1 签名 | **不需要** | ★省掉加密库移植★ |
| **服务器地址** | `{pk}.iot-as-mqtt.cn-shanghai.aliyuncs.com` | `bemfa.com` | 改字符串 |
| **端口** | 1883 | 9501（TCP）/ 9503（TLS） | 改数字 |
| **Topic 规则** | 平台自动生成，固定格式 | **用户自定义**（`{topic}`） | 灵活 |
| **OTA 固件托管** | ✅ 内置 | ❌ **没有** | ★要自己解决★ |
| **设备影子/物模型** | ✅ 有 | ❌ 没有 | 不用了 |

### 1.2 对四个人的影响总览

| 负责人 | 原任务 | 变化 | 工作量变化 |
|---|---|---|---|
| **A** | 4G 通信 + HTTP OTA 下载 | **HTTP 下载部分完全不变** | **不变**（已跑通） |
| **B** | BootLoader + Flash 分区 | **完全不变** | 不变 |
| **C** | 阿里云 MQTT + 加密 + OTA 包 | **全部重写**（变简单了） | **↓ 大幅减少** |
| **D** | SPI + 集成 | 基本不变 | 不变 |

### 1.3 最重要的三个结论

**结论 1：不用移植加密库了**

原本 C 要移植这三个文件（共 797 行）：

```
36号工程\HMAC\scr\utils_sha1.c
36号工程\HMAC\scr\utils_md5.c
36号工程\HMAC\scr\utils_hmac.c
```

巴法云不需要签名，**这三个文件全部不需要**。

> 例外：如果要做固件 MD5 校验，还是需要 `utils_md5.c`（只要这一个，约 200 行）

**结论 2：A 的工作完全不受影响**

```
AT+HTTPINIT              ← 不变
AT+HTTPPARA="CID",1      ← 不变
AT+HTTPPARA="URL","..."  ← 不变
AT+HTTPACTION=0          ← 不变
AT+HTTPREAD=0,256        ← 不变
```

**A 已经跑通了 GPRS 和拿到 IP（10.57.138.207），这条路继续走。**

**结论 3：多了一件新工作 —— 自己搭 HTTP 服务器放固件**

巴法云不托管固件文件，需要自己找地方放 `.bin`。

### 2.2 数据流：OTA 报文怎么传

**方案 A（推荐，最简单）：纯文本逗号分隔**

```
http://192.168.1.100:8000/fw.bin,31236,abc123def456...
        ↑ URL                    ↑ 大小  ↑ MD5（可选）
```

**优点**：解析简单，`strtok` 或 `sscanf` 几行就够
**缺点**：URL 里不能有逗号（正常 URL 不会用逗号）

**方案 B：JSON**

```json
{"url":"http://xxx.com/fw.bin","size":31236,"md5":"abc123"}
```

**优点**：标准，扩展方便
**缺点**：要写 JSON 解析（但只需要找几个固定字段，用 `strstr` 也能做）

**建议用方案 A**，初学者最容易上手。

### 3.2 C1：巴法云参数配置

**要改的文件**：`APP工程/user/api/common.h`

**原结构体（阿里云）**：

```c
typedef struct{
    u8  valid_cer;                              /* 0xDD = 有效 */
    u8  ProductKeyBuff[PRODUCTKEY_LEN+1];       /* 12 字节 */
    u8  DeviceNameBuff[DEVICENAME_LEN+1];       /* 33 字节 */
    u8  DeviceSecretBuff[DEVICESECRET_LEN+1];   /* 33 字节 */
    u8  Version_ABuff[VERSION_LEN+1];           /* 24 字节 */
    u32 OTA_firelen;
    u32 OTA_flag;
} AliyunInfo_CB;
```

**新结构体（巴法云）**：

```c
/*==================== 巴法云参数 ====================*/
#define BEMFA_UID_LEN         32        /* UID 正好 32 位 */
#define BEMFA_TOPIC_LEN       32        /* Topic 名字 */
#define VERSION_LEN           23        /* 版本号 23 位（保留） */

typedef struct{
    u8  valid_flag;                             /* 0xDD = 参数有效 */
    u8  UID_Buff[BEMFA_UID_LEN+1];              /* 33 字节，巴法云私钥 */
    u8  Topic_Buff[BEMFA_TOPIC_LEN+1];          /* 33 字节，订阅的 Topic 名 */
    u8  Version_ABuff[VERSION_LEN+1];           /* 24 字节，固件版本号 */
    u32 OTA_firelen;                            /* 固件大小（含 28 字节尾缀） */
    u32 OTA_flag;                               /* 0x5AA5C33C = 需要 OTA */
} BemfaInfo_CB;
```

**★★★ 关键警告 ★★★**

`common.h` 里的这个结构体 **两个工程（APP 和 BootLoader）必须完全一致**，否则：

```
APP 写 EEPROM 地址 0  →  BootLoader 读 EEPROM 地址 0
         ↓                          ↓
   结构体 A 布局              结构体 B 布局（不同）
         ↓                          ↓
    OTA_flag 写在偏移 110     BootLoader 读偏移 105
         ↓                          ↓
              读到的值不对 → OTA 永远不触发
```

**改这个文件前必须全组开会通知。**

**EEPROM 存储布局（地址从 0 开始）**：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 1 | valid_flag（0xDD = 有效） |
| 1 | 33 | UID |
| 34 | 33 | Topic |
| 67 | 24 | 版本号 |
| 91 | 4 | OTA_firelen |
| 95 | 4 | OTA_flag |
| **合计** | **99** | **（原来是 111）** |

### 3.4 C3：Topic 设计

**巴法云 Topic 是自定义的，建议这样设计：**

| Topic 名 | 方向 | 用途 |
|---|---|---|
| `ota{你的UID}` | 云端 → 设备 | **下发 OTA 命令**（核心） |
| `stm32{你的UID}` | 双向 | 通用消息（调试用） |

**举例**：假设 UID 是 `abc123def456...`

```
订阅：otaabc123def456
发布：stm32abc123def456
```

**下发 OTA 消息的格式（方案 A）**：

```
http://192.168.1.100:8000/fw.bin,31236,abc123def456789012345678901234
```

**设备端解析**：

```c
u8 CAT1_ParseOTA(char *msg)
{
    char *p;
    char *url;
    char *size_str;
    char *md5_str;

    /* 找第一个逗号 */
    p = strchr(msg, ',');
    if (p == NULL) return 1;          /* 格式不对 */
    *p = '\0';
    url = msg;                        /* URL 在逗号前面 */
    size_str = p + 1;

    /* 找第二个逗号 */
    p = strchr(size_str, ',');
    if (p != NULL)
    {
        *p = '\0';
        md5_str = p + 1;              /* MD5 在第二个逗号后面 */
    }
    else
    {
        md5_str = NULL;               /* 没有 MD5，跳过校验 */
    }

    /* 保存 */
    strcpy((char *)URL_ABuff, url);
    BemfaInfoCB.OTA_firelen = atoi(size_str);

    /* 打印调试 */
    Usart1_SendString("OTA URL: ");
    Usart1_SendString(url);
    Usart1_SendString("\r\n");

    return 0;
}
```

**★ 注意：`atoi` 只处理 u32 范围，固件大小一般不超过 4MB，够用。**

### 3.5 C4：打包升级包（28 字节尾缀）

**这个和阿里云方案完全一样，不用改。**

**升级包结构**：

```
┌──────────────────────────────┐
│                              │
│      固件本体（.bin）         │  N 字节
│                              │
├──────────────────────────────┤
│  CD EF CD EF                 │  4 字节：魔数（十六进制，不是 ASCII）

**用 `tools/ota_pack.py` 打包**（已经在仓库里）：

**输出示例**：

MD5: abc123def456789012345678901234
打包后: firmware_packed.bin (31264 字节 = 31236 + 28)
```

**B 的 BootLoader 会校验这个尾缀**，格式错了不会升级。

## 第七部分：固件文件放哪里（新增任务）

### 7.1 巴法云不托管文件

**需要自己找地方放 `.bin` 文件。**

### 7.2 方案对比

| 方案 | 优点 | 缺点 | 适用阶段 |
|---|---|---|---|
| **电脑开 HTTP 服务** | 最简单，改完立刻生效 | 电脑必须开着，同一局域网 | ★调试阶段★ |
| **Gitee 仓库 raw 直链** | 免费，稳定 | 需要 Gitee 账号，raw 链接可能有限制 | 演示阶段 |

| 方案 | 说明 | 难度 |

### 9.2 保底方案：本地升级（如果云端全崩）

**如果 4G + 巴法云都走不通，改成本地升级：**

```
电脑串口 ──Xmodem协议──→ STM32
                          ↓
                    写 W25Q128
                          ↓
                    重启 → BootLoader 搬移
```

**优点**：
- 不依赖网络
- Xmodem 是标准协议，代码量小（约 200 行）
- **一周内一定能做完**

**缺点**：
- 不是"远程 OTA"，演示效果差
- 要连电脑

**建议：把本地升级作为 Plan B，先写出来保底，再攻云端。**

## 附录 C：今天踩过的坑（给全组参考）

| # | 坑 | 现象 | 原因 | 解决 |
|---|---|---|---|---|
| 1 | **IROM1 偏移** | 烧录成功但串口无输出 | APP 从 0x08008000 启动，但没烧 BootLoader | 调 APP 时改回 0x08000000 |
| 2 | **USART3 波特率算错** | AT 完全无响应 | `36000000/16/brr` 全整数运算，小数丢失，误差 2.8% | 改用整数算法（先算 16 倍再拆） |
| 3 | **逻辑反转** | 模块回 READY 却报"SIM卡未准备好" | `if (!CAT1_SendAT(...))` 用反了 | 去掉 `!` |
| 4 | **中断里发数据** | 串口死锁 | 中断里调 `SendString`，等 TC 标志死循环 | 中断只收数据+置标志 |
| 5 | **编码不统一** | VS Code 报"未定义标识符" | `stm32f10x.h` 是 GBK，其他是 UTF-8 | 全部转 UTF-8 BOM |
| 6 | **IntelliSense 头文件** | 找不到 `uint32_t` | 用 ARMCC 头文件，GCC 模式解析失败 | 手写 9 个 stub 头文件 |
| 7 | **模块只在开机读卡** | 先上电后插卡一直报 CME 10 | 模块开机时检测 SIM | 断电→插卡→上电 |
